# BYRBT Tools

<img src="assets/icon.svg" width="64" height="64" alt="BYRBT Tools 图标">

面向桌面 Chrome / Edge + Tampermonkey 的 BYRBT 第三方工具箱，与站点官方无隶属关系。仅在 `https://byr.pt/*` 生效。当前第一个功能是按数字 UID 分层屏蔽用户，覆盖群聊、趣味盒、论坛和评论等页面，后续功能可接入同一工具箱。

[安装最新版](https://github.com/UnbalancedCat/byrbt-tools/releases/latest/download/byrbt-tools.user.js) · [版本记录](https://github.com/UnbalancedCat/byrbt-tools/releases) · [反馈问题](https://github.com/UnbalancedCat/byrbt-tools/issues) · [MIT 许可](LICENSE)

## 安装

1. 从浏览器官方扩展商店安装 Tampermonkey。根据其提示启用用户脚本执行权限；相关说明见 [Tampermonkey FAQ](https://www.tampermonkey.net/faq.php)。
2. 点击上方“安装最新版”，在 Tampermonkey 中确认名称为 **BYRBT Tools** 后安装。无需下载源码 ZIP；若只显示源码，可将完整 `.user.js` 复制到油猴的新脚本编辑器并保存。
3. 刷新已登录的 BYRBT 页面，在顶部“管理组”右侧打开“工具箱”。如未出现，检查脚本是否启用、网址是否为 `https://byr.pt/`，以及扩展的站点访问和用户脚本权限。独立群聊、趣味盒页使用页首入口，也可从油猴菜单打开。

曾安装 **BYRBT Tools · 用户屏蔽** 的用户，请先按 [迁移指南](docs/MIGRATION.md) 导出配置、停用旧脚本，再安装新版、导入并保存；不要同时启用两份。后续同名称版本通过 Releases 提供自动更新地址，检查频率由油猴设置控制。

**初装名单为空。** 在“工具箱 → 用户屏蔽 → 名单”添加 UID 或个人页链接，再点击“保存设置”。用户名旁悬停/聚焦的快捷按钮和个人页内嵌按钮，会进入工具箱并填入明确的加入或移除草稿；保存前不改变实际屏蔽状态。不会更改 BYRBT 自带黑名单。

当前版本 **0.3.0**：首次公开发布，采用独立产品名称、原创内嵌图标和稳定更新入口。继承 0.2.2 的原生表格、底部统一保存、同页返回和不撑高行的快捷按钮。配置格式仍为版本 1，但旧名称安装需要上述一次迁移。六套主题复用站点 CSS 并继承字体大小；无边框主题仅在插件表格内补充淡色网格，不提交网站设定。实际覆盖与待验证场景见 [验收记录](docs/VALIDATION.md)。

若已安装但没有面板，先确认油猴中脚本已启用且网址匹配，再按 [官方执行权限说明](https://www.tampermonkey.net/faq.php?q=Q209#Q209) 检查“允许运行用户脚本”或开发者模式。变更后刷新站点；仍无效时可重启 Tampermonkey 扩展或浏览器，再检查。不要把扩展已安装等同于脚本已执行。

## 使用规则

| 层级       | 主要范围                                                              | 默认 |
| ---------- | --------------------------------------------------------------------- | ---- |
| 互动内容   | 群聊、论坛主题/楼层、趣味盒及评论、通用评论、普通用户站内信、发言历史 | 开启 |
| 资源与作品 | 种子、试种、求种/应求、字幕、Banner、竞猜的可识别作者内容             | 关闭 |
| 其他身份   | 排行、徽章持有人、赠送者、最近回复者、日志、同伴、个人资料            | 关闭 |

每个用户可针对每一层选择“继承全局 / 屏蔽 / 保留”。“规则”页管理全局默认规则，“导入导出”页管理 JSON 和原生黑名单导入。所有名单、规则和导入操作都先进入同一份草稿，点击“保存设置”后统一应用；“放弃修改”恢复最新已保存配置。

点击“临时显示本页”可立即恢复原页面及已加载同源 iframe 内的内容，不必保存；再次点击恢复屏蔽。底部“返回原页面”与顶部指向原页面的导航都直接恢复原内容，不刷新、不重载 iframe，保留临时显示状态；首页 `/` 与 `/index.php` 视为同一页面。刷新或进入其他页面后重置。规则匹配数量始终基于已保存配置，临时显示时不代表当前隐藏数量。

用户名旁的快捷按钮在悬停或键盘聚焦时显示，使用不占排版空间的紧凑定位，不撑高文字行、不挤动后续文字。按钮显示时可能短暂覆盖紧邻的内容，移开鼠标和焦点后隐藏。

工具箱使用 `#byrbt-tools/user-blocking/list`、`rules`、`transfer` 子页，支持前进、后退和刷新。返回原页面会恢复原 hash、滚动位置及导航选中状态，保留原 iframe。存在未保存修改时，离开需选择继续编辑或放弃；刷新/关闭使用浏览器的离开提醒，具体显示由浏览器控制。草稿不会跨页面持久保存。

“保存设置 / 放弃修改 / 返回原页面”统一位于当前子页最底部，正常随页面滚动，不悬浮。保存会应用三个子页的全部草稿。错误、冲突与未保存状态也位于底部；失败时自动定位反馈。快捷入口先定位目标用户行或待执行取消提示，不会直接跳到保存按钮。名单默认显示 100 项，可继续加载；窄窗口只对名单表格提供局部横向滚动。

屏蔽发起者不连带隐藏其他人的回复。未知作者、匿名资源、纯文字引用仍保留。明确 UID 的 @ 显示为“已屏蔽用户”；引用只从引用归属信息识别作者，不拿引用正文里被提及的人当作者。列表没有作者 UID 时不后台抓取详情，因而不会保证每一个标题都能被过滤。

站务页面及已识别的公告/版规首帖保留，普通回复照常过滤。当前有明确识别依据的是规则/FAQ/管理联系页、最新公告版块和已核查的版规/教程主题；新增站务布局需要维护，脚本不会靠“管理员姓名颜色”豁免其所有发言。

## 存储与恢复

- 名单保存在 Tampermonkey 存储中，按当前登录账号 UID 隔离，同账号标签页共享更新。未确认登录账号时不应用名单。
- 导入 JSON 合并到当前草稿：保留草稿的全局设置和已有用户的单人规则；新用户保留导入的单人规则，跳过当前登录账号。批量校验失败不部分添加；放弃编辑或切换账号会取消过期异步导入结果。支持从其他账号的导出文件迁移名单。
- 导出仅包含已保存的账号 UID、名单展示名、三层规则和配置版本，未保存草稿不包含在内；不包含 cookie、密码、passkey、聊天或邮件正文。
- 导入站点黑名单仅在点击按钮时读取 `/friends.php`，不执行站点增删操作，也不导入好友。
- 独立打开的趣味盒/群聊页缺少账号导航时，会只读请求一次首页确认账号。除此之外不自动补查作者、不建立内容抓取队列、不上传内容。
- 取消屏蔽并保存后恢复原内容与原事件监听。关闭脚本并刷新页面可完全停用；升级前可导出名单备份。
- 其他标签页保存时，实际过滤立即更新，当前草稿保留。保存会比较编辑基线、草稿和最新配置：独立字段自动合并，同字段冲突及删除/修改冲突需逐项选择保留哪一边。解决后保存仍会在存储锁内重新检查；若远端又有新变化，会重新提示冲突。存储失败保留草稿与错误信息。

## 开发

需要 Node.js 24。

```text
npm ci
npm run check
```

`src/core.js` 定义 UID 与配置规则，`store.js` 封装油猴存储与同账号更新，`drafts.js` 管理草稿和三方合并；`shell.js` 管理站内导航、路由和功能注册（id/name/mount/route/unmount），`ui.js` 实现用户屏蔽视图与快捷入口。`adapters.js` 输出页面内容单元，`engine.js` 管理动态观察与可逆隐藏，`main.js` 协调账号、页面和 iframe。esbuild 生成单文件安装包，无运行时 CDN 依赖。

配置格式为版本 1：`{ version, accountId, defaults, users }`。`users` 以规范化 UID 为键，每项为 `{ uid, name, overrides }`；`defaults` 包含 `interaction / resource / identity`，`overrides` 仅保存需要覆盖的布尔字段。非法配置整体拒绝，不静默重置已有数据。

`npm run preview` 只绑定本机回环地址。其 `harness.js` 将**实际构建包**配合内存 GM 模拟器用于开发验证，不属于发布包、不写入扩展真实存储，刷新测试页面即清除。不要将它当作已完成扩展安装测试的证据。

安装包只使用本机配置存取、配置变更监听与油猴菜单接口，不申请跨站请求、Cookie 或剪贴板权限。不上传内容，不使用分析统计服务；图标内嵌在脚本中。升级检查由 Tampermonkey 访问 GitHub 发布地址完成。

测试结果与当前限制见 [覆盖矩阵](docs/COVERAGE.md) 和 [验收记录](docs/VALIDATION.md)；维护者发布步骤见 [发布指南](docs/RELEASING.md)。提交反馈时请勿附带私信正文、凭据、个人配置或未脱敏截图。
