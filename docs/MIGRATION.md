# 从旧名称脚本迁移

`BYRBT Tools · 用户屏蔽` 与 `BYRBT Tools` 名称不同，安装时可能被视为两个脚本；不要假定旧版存储自动迁移。

1. 在旧脚本工具箱中先保存需要保留的修改。进入“导入导出”，导出 JSON；导出不包含未保存草稿。
2. 将文件保存在仓库外或本地 `backups/` 目录，勿上传 GitHub、Issues 或聊天。
3. 在 Tampermonkey 中停用旧名称脚本，暂不删除。
4. 从 [最新 Release](https://github.com/UnbalancedCat/byrbt-tools/releases/latest) 安装 `byrbt-tools.user.js`，确认名称为 **BYRBT Tools**。
5. 刷新已登录站点，在新版“导入导出”中选择备份文件。检查名单和规则，点击“保存设置”。
6. 刷新复核保存结果和屏蔽效果；确认 Tampermonkey 中只有新版启用，站点只有一个“工具箱”入口。
7. 验证成功后可移除旧脚本，继续保留 JSON 备份。Chrome、Edge 分别操作；同一浏览器的不同站点账号分别导出、导入。

若迁移失败，停用新版、重新启用旧版并刷新，原配置仍在。没有名单的旧安装也应停用，避免重复运行。

若已经同时启用了两份，请先只启用旧版导出配置，再只启用新版导入。每次切换后刷新站点，确认仅有一个“工具箱”入口再操作；两个实例可能读取不同存储，不能通过其中一个显示的名单推断另一个已迁移。

配置仍使用版本 1，按站点登录账号隔离。导入会合并到当前草稿，已有用户的个性规则优先；需要完整迁移时，应先在空的新配置中导入。脚本不会把配置上传到 GitHub。

## 后续更新

新版通过 Release 的 `.meta.js` 检查版本，随后下载 `.user.js`。检查频率由 Tampermonkey 设置决定，不保证发布后立即更新；也可在油猴中手动检查更新。

若自动更新失败，从同一项目的最新 Release 重新安装新版。后续保持 `@name`、`@namespace` 不变，正常同身份升级无需重复导出导入；仍建议定期保留本地备份。
